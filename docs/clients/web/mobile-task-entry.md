# スマホでの課題登録

## ユースケースと判断（2026-10-12）

教員の説明やTeamsの通知から、一つの独立した課題が発生したことを知り、その場で忘れないうちに登録する。ユーザーは通知の内容を覚えながら入力するため、一覧との重なりや画面遷移の解釈、任意項目の判断に注意を使わせない。

従来の引き出し型フォームは、画像欄や期限の範囲選択で内容が長くなり、Safariのブラウザバーやソフトウェアキーボードによって利用可能な高さが縮むと、フォームや登録ボタンへ到達しにくかった。高さの固定やドラッグ操作が絡むUIで対処するより、通常のページスクロールを採用する。

## 採用した構成

- 768px未満では一覧の新規作成ボタンとキーボードショートカットから `/tasks/new` に移動する。直接リンク・ブックマークも可能。既存の認証ガードで保護する。
- タイトル・教科・期限を縦に並べる。既存APIが要求する三項目が揃えば登録可能。タイトルへ自動フォーカスせず、最初からキーボードで画面を狭めない。
- 提出必須・自己採点・タイプ・説明・画像は「詳細を追加（任意）」で展開する。詳細が不明でも先に登録し、後から編集できる。
- 期限はページ内で展開し、日付は端末のネイティブ入力を利用する。授業外・1コマ・2コマ・範囲選択を維持し、適用までは確定値を変えない。閉じた場合は未適用の変更を破棄する。
- 文字入力はスマホで16px、主要操作は高さ44px以上。登録ボタンはフォーム末尾に置き、キーボードや期限選択を覆う固定フッターを避ける。
- 登録中はフォームと登録操作を無効化し、失敗時には入力を保持する。成功後は一覧へ戻る。一覧が空でもスマホでは別のインラインフォームを重複表示しない。
- PCは既存のダイアログを維持し、高さを画面内に制限して内部スクロールを許可する。期限ポップアップにも画面幅・利用可能高さの制限を付ける。

## 検証と限界

Playwrightで320px/390px幅、360pxまで縮めた画面高さ、長い説明、画像添付、期限の範囲選択、未適用の期限変更の破棄、失敗後の再試行と一覧への復帰を確認した。Chrome系の全33件のブラウザテスト、およびWebKitでの新規登録・再試行の3件が成功。既存のPC登録・編集・画像・検索も回帰確認した。WebKitではサービスワーカーによってAPIモックを迂回するため、モックを使うテストファイル内でサービスワーカーを無効化し、CORSヘッダーも明示して検証した。

セルフレビューでは二重送信を防ぐ同期的な送信ガード、失敗時の入力保持、ページの認証・ポリシー同意確認、期限の確定値と編集中の値の区別を確認。検証で見つかった範囲選択が1限から拡張される問題と、非表示の画像入力が横幅を押し広げる問題も修正した。

画面高さを縮める検証はソフトウェアキーボードの実機再現ではない。iPhone Safariのネイティブ日付UIとキーボードの最終確認は実機が必要。入力の保持は同一ページ内でのAPI失敗に対応し、ページ再読み込みや離脱後の永続的な下書き保存は今回の対象に含めない。

## 文言の調整（2026-10-13）

入力欄を見れば分かる内容を説明文として重ねると、登録時に読む量が増える。「タイトル・教科・期限だけで登録できます。詳細は後から編集できます。」は削除し、見出しと入力欄で登録の流れを伝える。
